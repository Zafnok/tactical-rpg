# ADR-0016: Font atlas format and glyph blitting

- **Status:** Accepted
- **Date:** 2026-09-25
- **Related tickets:** 0203, 0011, 0205

## Context

ADR-0003 has `app` blit a `GlyphBuffer` with a bundled bitmap font; ADR-0012
fixes 8×16 cells and integer scaling. We need a font file the game can load
cheaply on desktop and WASM, a way to regenerate it, and a scaling rule that
stays crisp on Windows displays set to 125–175% scaling.

## Decision

1. **Font:** Terminus Font 8×16 (OFL-1.1). The choice and licence notes are in
   `assets/fonts/README.md`.
2. **Atlas format:** `assets/fonts/atlas.png` (white glyphs on transparent,
   `columns` cells per row, row-major) plus `assets/fonts/atlas.ron`, a
   `trpg_content::FontAtlasDef { cell_w, cell_h, columns, glyphs: char → index }`.
   Both are generated by `cargo xtask font-atlas <font.bdf> <out-dir>` from a
   BDF kept in `assets-src/` (not embedded), and committed. An `xtask` test
   fails when the committed atlas is stale.
3. **Validation:** `trpg-content` checks every `REQUIRED_GLYPHS` char is
   present, indices are unique and fit the PNG (size read from the PNG header;
   no image decoder in `content`).
4. **Blitting:** `app::render::Renderer` draws per cell a background rectangle
   (skipped when it equals the palette's `black`) and the glyph's atlas rect
   tinted with the fg colour, `FilterMode::Nearest`. A glyph not in the atlas
   draws as `?` in magenta and is logged once.
5. **Scaling:** `trpg_ui::console::layout()` (pure, unit-tested) picks the
   largest integer scale ≥ 1 that fits and centres on whole pixels. The window
   is `high_dpi`, and `layout()` receives the **physical** framebuffer size
   (logical size × DPI, rounded), so "integer scale" means real screen pixels.
   A window smaller than 1× crops the console evenly on all sides.

## Consequences

- Adding glyphs means widening `ATLAS_RANGES` in `xtask` and regenerating; the
  game build never needs the tool.
- Swapping the font is a data change (new BDF, regenerate), as long as the new
  font is 8×16 and covers `REQUIRED_GLYPHS`.
- Without `high_dpi`, Windows would bitmap-stretch the window by its scaling
  factor (e.g. 1.75×), blurring glyphs; with it, the default window is sized in
  physical pixels (1640×1064, room for 2×) and may look small on very
  high-DPI screens. Players can resize or maximise; the options screen may add
  a window-size setting later.
- Drawing ~3,200 textured quads a frame is well within macroquad's batching.

## Alternatives considered

- **TTF font rendered by macroquad** — glyph metrics and hinting vary by
  size and platform; loses the exact pixel look ADR-0012 asks for.
- **Parsing the BDF at runtime** — puts a parser and a 180 KB source file in
  every build for no gain.
- **Scaling in logical units (`high_dpi = false`)** — simplest, but blurry on
  scaled Windows displays, which is most laptops.
- **Rendering to an 800×512 render target, then scaling it** — equivalent
  output, more moving parts; direct drawing is enough.
